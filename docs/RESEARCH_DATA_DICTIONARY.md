# Research Data Dictionary

## Purpose

This document specifies the structure and contents of Socra research exports. Every export is a pseudonymized, read-only projection of analytics events from consenting study participants, captured under a specific study condition (control, unrestricted AI, or Socratic AI) and frozen in an immutable dataset manifest. Exports are generated by and audited for research administrators only.

## Row Grain

One row per `AnalyticsEvent` marked with `status = "ACCEPTED"` from a participant in the study.

**Exclusions:**
- Participants with `StudyParticipant.withdrawnAt` not null (withdrawn after enrollment).
- Participants with `StudyParticipant.consentStatus` in `DECLINED` or `WITHDRAWN`.
- Events with `status = "QUARANTINED"` (failed validation; never exported).
- Events with `eventName` starting with `"research_"` (internal tracking events).

**Inclusion rule from export.ts:** A participant is eligible if they have a `StudyParticipant` row with `consentStatus` in `{CONSENTED, NOT_ASKED}` and `withdrawnAt` is null. An event is included if it has `status = "ACCEPTED"`, belongs to an eligible participant in that course, and does not match the exclusion rules above.

## Pseudonymization

**Method:** HMAC-SHA256 (deterministic, key version 1).

**Formula:** `p_` + first 24 hex characters of `HMAC-SHA256(user:${userId}, RESEARCH_PSEUDONYM_SECRET)`.

**Properties:**
- Deterministic for a given secret; the same userId always produces the same pseudonymous ID.
- Computed at export time via `pseudonymFor()` in `src/server/events/pseudonym.ts`.
- The bidirectional identity mapping is stored in the protected `ResearchParticipantMapping` table (separate schema, access audited).
- Exports never include the mapping table and therefore never join to raw identities.

## Forbidden Fields

The following fields are deliberately never exportable. Requests naming these receive a specific refusal.

- **Personal identifiers:** name, email, userId, actorId, sessionId, ip
- **Raw content:** message, content, text, code, answer, transcript

In addition, the following are always listed in the manifest's `fieldsExcluded`:

- names
- email addresses
- internal user ids
- session ids
- raw message content
- code and answer content
- hidden tests

## Study Conditions and Assignment

### Condition Values

Study condition is a three-level factor assigned to each participant per course:

- **CONTROL:** No AI assistance; baseline condition for comparison.
- **UNRESTRICTED_AI:** Full access to Socra in all modes without policy guardrails.
- **SOCRATIC_AI:** Socra with graduated intervention levels (0–6), policy checks, and resource retrieval.

### Changing a Condition

Condition changes are never silent and never automatic:

1. A `StudyConditionChange` row is created with:
   - `participantId`: The participant whose condition changed.
   - `fromCondition` and `toCondition`: Before and after.
   - `reason`: A required string explaining why (IRB amendment, consent modification, etc.).
   - `changedById`: ID of the admin who approved the change.
   - `changedAt`: Timestamp of the change.

2. An `AuditLog` entry is written with:
   - `action`: "study.condition_changed" (or similar).
   - `targetType`: "StudyParticipant".
   - `targetId`: The participant ID.
   - `metadata`: Includes the change details.

3. Future events from that participant carry the new condition in their `researchCondition` field; historical events retain their original condition (stamped at event time).

## Export Filters and Formats

### Filters

Exports accept optional filters (all are optional; omit any to include all values):

- **courseId:** Restrict to one course.
- **assignmentId:** Restrict to one assignment.
- **from, to:** Date range (inclusive start, exclusive end). Filters events by `eventTime`.
- **eventNames:** Array of event names to include (e.g., `["practice_answered", "socra_response_completed"]`). Automatically excludes events matching `"research_*"`.

### Formats

Exports are delivered in one of two formats:

- **CSV:** Comma-separated values with header row. Column order is always the registry order (stable across requests). Boolean values are `true` or `false`. Datetimes are ISO 8601. Null values are empty cells. **Formula injection guard:** If a cell value starts with `=`, `+`, `-`, `@`, tab, or carriage return, it is prefixed with a single quote (`'`), making it a literal string in Excel/Sheets.
- **JSON:** Array of objects (one per row), each with field keys as property names. Each property is either a string, number, boolean, or null. Datetimes are ISO 8601 strings.

### Example Filter (JSON)

```json
{
  "courseId": "course123",
  "assignmentId": "assign456",
  "from": "2024-01-01T00:00:00Z",
  "to": "2024-12-31T23:59:59Z",
  "eventNames": ["practice_answered", "socra_response_completed", "code_run_completed"]
}
```

All filter fields are optional. If omitted, no restriction is applied on that axis.

## Reproducibility Fields

When present in the export, the following fields enable reproducibility of AI-mediated behavior:

- **schemaVersion:** Event schema version used to parse metadata. Fixed per event.
- **appVersion:** Client app version. Fixed per event.
- **model:** AI model ID (e.g., "gpt-4-0125-preview"). Varies per Socra response.
- **promptVersion:** Prompt template version (e.g., "protected-v1"). Varies per Socra response.
- **policyVersion:** Socra policy version (e.g., "v1", "v2"). Varies per interaction.
- **assignmentVersion:** Assignment version. Fixed for the assignment at publish time.
- **questionVersion:** Question version. Fixed for the question at publish time.

All version fields are strings. When a field's value is not applicable to an event, it is null in the export.

## Audit Trail

Every research export operation is audited:

| Action | Timing | Logged Data |
|--------|--------|-------------|
| `research.export_requested` | When the export request is created | filters, fields, format, estimatedRows |
| `research.export` | When the export completes successfully | manifestId, datasetVersion, rowCount, checksum, format, fields, filters |
| `research.export_download` | When a researcher downloads the completed export | checksum, rowCount |
| `research.export_failed` | If the export fails | error message |

All audit entries include:

- **actorId:** The RESEARCH_ADMIN user who requested the export.
- **targetType:** "ResearchExport".
- **targetId:** The export ID.
- **courseId:** The course (if filtered), or null.
- **createdAt:** Timestamp of the action.

Audit logs are append-only and never modified or deleted during normal operation.

## CSV Formula Injection Mitigation

When exporting to CSV, any cell value that starts with `=`, `+`, `-`, `@`, tab (`\t`), or carriage return (`\r`) is prefixed with a single quote (`'`). This ensures that spreadsheet applications (Excel, Google Sheets, etc.) interpret the value as a literal string, not a formula.

**Example:**
- Raw value: `=SUM(A1:A10)`
- Exported value: `'=SUM(A1:A10)`
- Spreadsheet interpretation: Literal string `=SUM(A1:A10)`, not a formula.

## Delivery and Storage

- **Inline threshold:** Exports with ≤5000 rows are generated and returned immediately.
- **Queued:** Exports with >5000 rows are enqueued to a worker, which generates them asynchronously. Status transitions from "REQUESTED" → "RUNNING" → "COMPLETED" (or "FAILED").
- **Storage:** Completed exports are stored by key `research-exports/{exportId}.{csv|json}`.
- **Checksum:** The file content is verified against the manifest's `checksum` field before serving to guard against corruption.

## Notes

1. **Consistency:** Every field exported is extracted via an explicit function in the EXPORT_FIELDS registry. Metadata is never copied wholesale; unexpected keys cannot leak.
2. **Determinism:** The pseudonym for a given user and secret is identical across exports, allowing linkage without re-identification.
3. **No student content:** Raw answers, code, messages, and helper text are forbidden and never appear in any export, regardless of field selection.
4. **No internal IDs:** User IDs, session IDs, and actor IDs are forbidden; only the pseudonymous participant ID is exported.
5. **Versioning:** Every exported dataset is versioned and immutable once frozen, with a manifest recording all parameters and a checksum for integrity.
